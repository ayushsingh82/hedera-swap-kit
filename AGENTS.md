# Agent instructions

Briefing for coding agents in this repo (Cursor, Claude Code, Codex). Claude Code loads it through `CLAUDE.md`.

`hedera-swap-kit` is a Scaffold-HBAR template to swap, pay, pay out and schedule on Hedera, built on SaucerSwap V2 and the Hedera Schedule Service (HSS). The Hardhat package has three contracts (`SwapHelper`, `ScheduledSwap`, `BatchPayout`) and the Next.js app has a swap component kit plus pages for each use case. There is no Foundry package.

Read [README.md](README.md) first for the Hedera concepts (association, WHBAR, tinybar vs weibar). Read [docs/architecture.md](docs/architecture.md) before changing a contract flow and [docs/use-cases.md](docs/use-cases.md) before changing a use case.

## Commands

Run from the repo root.

```bash
npm install

npm run hardhat:compile
npm run hardhat:test                                  # contract tests
npm run hardhat:chain                                 # local Hedera-forked node on 8545
npm run hardhat:deploy -- --network localhost         # or hederaTestnet / hederaMainnet
npm run init                                          # create a deployer wallet, save the key to .env
npm run doctor                                        # check the setup and say how to fix it
npm run deploy:testnet                                # deploy every contract to testnet
npm run demo:swap | demo:pay | demo:payout | demo:dca # one real testnet transaction each, needs HBAR

npm run next:dev                                      # http://localhost:3000
npm run next:test                                     # swap-logic unit tests
LIVE=1 npm run next:test                              # also runs a live testnet quote
npm run next:check-types
npm run next:lint
npm run next:build

npm run hardhat:account:generate                      # or hardhat:account:import
```

Before finishing a change, run the checks that match what you touched: `next:test`, `next:check-types`, `next:build` for the frontend and `hardhat:test` for contracts. CI runs lint, types, unit tests and the build.

`hardhat:deploy` without `--network` targets the in-process network, not the long-running fork. Pass `--` before `--network`.

## Hedera rules that are easy to get wrong

- **Association.** An account must be associated with a token to hold it, but accounts that allow automatic associations (`max_automatic_token_associations` of -1, the default for new accounts, contracts included) get it on arrival. `SwapHelper` pulls its input token itself, so it needs an explicit `associate`. Native HBAR needs neither.
- **Accounts must exist.** Sending HBAR or a token to an address with no Hedera account aborts the whole transaction (`INVALID_ALIAS_KEY`) and a `try`/`catch` cannot catch it. Check with the mirror node first, as `usePayoutChecks` does.
- **HBAR vs WHBAR.** Paths use the WHBAR **token** id (`0.0.15058` testnet, `0.0.1456986` mainnet), never the WHBAR contract. HBAR in sends `msg.value`; HBAR out goes through `unwrapWHBAR`. Never wrap by hand.
- **Decimals.** Inside contracts and in this kit, HBAR is in tinybar (8 decimals). JSON-RPC `msg.value` is weibar (18 decimals): multiply tinybar by `WEIBAR_PER_TINYBAR` (`10^10`) only when sending a transaction value.
- **IDs.** Hedera `0.0.N` maps to an EVM address by padding `N` to 20 bytes: use `idToEvmAddress`. Do not hardcode hex.
- **Gas.** Hedera calls need an explicit `gas`. The hooks set it; keep that when adding a write. Hedera bills gas used, but the sender must hold `gas limit x max fee` up front. ethers defaults `maxFeePerGas` to twice the gas price, so scripts pass `maxFeePerGas` equal to the gas price.
- **Schedule Service (0x16b).** `scheduleCall` returns a response code instead of reverting (22 is success). A scheduled call runs as the contract itself. The contract must hold `gas limit x gas price` when it runs, and a run that schedules the next one used about 1.4M gas, so size gas limits for that. See `ScheduledSwap`.
- **Solidity.** `reference` is a reserved word; use `batchId` or similar.
- **Fees accrue.** The integrator fee stays in `SwapHelper` and is withdrawn by the owner. Do not change it to pay out per swap: a transfer to an unassociated account reverts.

## Conventions

- Contract and token ids come from `utils/swap/config.ts` (frontend) and `packages/hardhat/utils/saucerswap.ts` (Hardhat). Keep both in sync. Do not scatter addresses through components.
- Business logic that can be pure goes in `utils/swap/` with a test in `utils/swap/swap.test.ts`. Components stay thin.
- Hooks live in `hooks/swap/` and are exported from its `index.ts`. Components live in `components/swap/` and are exported from its `index.ts`.
- Use the existing scaffold hooks for contract reads and writes where they fit: `useScaffoldReadContract`, `useScaffoldWriteContract`, `useDeployedContractInfo`. Not `useScaffoldContractRead` or `useScaffoldContractWrite`.
- UI uses DaisyUI classes and `@scaffold-hbar-ui/components` (`Address`, `Balance`, and so on) before raw Tailwind.
- Imports in `packages/nextjs` use the `~~` alias, for example `~~/utils/swap/math`.
- Pages that use hooks need `"use client"`.
- Naming: `UpperCamelCase` types and components, `lowerCamelCase` variables and functions, `CONSTANT_CASE` constants, `snake_case` for Hardhat deploy file names after the number prefix.
- Prefer `type` over `interface`. No `T` prefix. Let TypeScript infer. Comments only where the code is not obvious: say why, not what.
- Every component handles loading, empty and error states.

## Do

- Add a test when you change swap math, route finding, payout parsing, auto-buy helpers or any contract. Contract tests use `MockSwapRouter` and `MockScheduleService` (placed at `0x16B` with `hardhat_setCode`).
- Add a use case by: a contract path (or reuse `SwapHelper`), a hook, a component in `components/use-cases/`, a page, a Use cases menu entry in `components/Header.tsx`, a guide in `docs/use-cases.md` and in-app under `app/docs/`, and a demo script.
- Redeploy after changing `SwapHelper`; deploy regenerates `deployedContracts.ts`.
- Check a Hedera id on the mirror node before adding it to config.
- Keep docs in `docs/` and the README in step with code changes.

## Don't

- Don't commit `.env`, private keys or encrypted keystores.
- Don't edit `packages/nextjs/contracts/deployedContracts.ts` by hand.
- Don't send HBAR value in tinybar or read it back in weibar without converting.
- Don't call WHBAR's `deposit` or `withdraw` from the kit. The router does the wrapping.
- Don't claim something works on a network until it has been run there. Record the Hashscan link instead.
- Don't assume a failed row in a batch is caught: only reverts inside the call are. Account-level failures abort everything.
